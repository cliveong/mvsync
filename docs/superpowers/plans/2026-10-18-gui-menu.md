# GUI Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `run.bat` console menu with a single Tk window that exposes Play, Scan, Fix, and Doctor as buttons with a live log pane, so everyday use never needs the console.

**Architecture:** A new main window (`gui.py:MainWindow`) reusing the layout patterns already proven in `FixerWindow`. Long operations run on worker threads and print into a thread-safe `LogSink` that the Tk main loop drains; hotkeys the play loop needs become a `KeySource` the GUI feeds from key bindings and on-screen buttons. `Fix` launches `FixerWindow` in a separate process, never a second Tk root in a thread. The console menu and every `run.bat <cmd>` subcommand stay intact; only the no-argument launch changes.

**Tech Stack:** Python 3.12, tkinter (stdlib), threading, subprocess, existing `run_play` / `scan_with_candidates` / `doctor` entry points. No new dependencies.

**Spec:** None standalone. Decisions come from the 2026-10-18 conversation: migrate every menu option into the GUI, GUI first, CLI stays as a fallback.

## Global Constraints

- Windows-only by design; no cross-platform shims.
- No new runtime dependencies (tkinter, threading, subprocess are stdlib).
- Every path through `paths.py`; nothing absolute in committed code.
- Tests run with no network, audio devices, SMTC, or mpv, and **never construct a `tk.Tk()` root** (that needs a display). Test pure logic only, matching the existing `tests/test_gui.py` pattern of testing helpers rather than widgets.
- Console prefixes stay `[scan]`, `[play]`, `[search]`, `[doctor]`; this work adds `[gui]`. AGENTS.md is updated in Task 6, the last task.
- ruff line length 100; type hints on public functions; short docstrings over comments.
- TDD: failing test, run it, implement, run it, commit.
- One `session.claim` at a time. The GUI must never steal the lock, and must never write the lock file itself (only `session.claim` may).

## Review Focus

Failure modes most likely to bite a real user, most likely first; each has coverage in the task that owns the code.

1. **Hotkeys do nothing during play.** Two independent causes, both must be handled: (a) the mpv window steals focus so Tk key bindings never fire, fixed by on-screen buttons; (b) the play loop only reads one key per `POLL_S` (0.25 s, `sync_runtime.py:38,150,256`), so repeated `[`/`]` nudges land at 4 per second, and (c) **nothing polls keys at all while a video is downloading**, because `_wait_media_loaded` budgets 90 s (`sync_runtime.py:43,112`) and the rough-mode fetch at `sync_runtime.py:379` blocks too. (Task 2 tests, Task 3 buttons, Task 3 manual check; the startup gap is a documented limitation, see Notes.)
2. **Partial or interleaved output lines** from concurrent worker threads garble or lose log text. (Task 1 tests)
3. **The GUI freezes** because an operation ran on the Tk main thread. Doctor, Scan, and Play all run on worker threads. (Task 3)
4. **Closing the window mid-operation** loses the final log line, leaves `data/session.lock` behind, and can orphan an `mpv.exe` that keeps playing a muted video: `_run_play`'s cleanup (`sync_runtime.py:122-125`) lives on the worker thread, and nothing in the project kills mpv if the process dies. (Task 3 closing flag, Task 3 manual check)
5. **`[` and `]` stop working on a non-US keyboard layout**, because `event.char` reports jamo on a Korean IME layout. `q`/`r`/`p` are layout-independent. (Task 3, match on `event.keysym`)
6. **A second `Tk()` root is created off the main thread** and hangs, because Tk is not thread-safe. `FixerWindow` must run as a separate process. (Task 3)

### Task 1: Log sink and key source

**Files:**
- Create: `src/mvsync/gui_console.py`
- Create: `tests/test_gui_console.py`

**Interfaces:**
- Consumes: nothing new.
- Produces in `src/mvsync/gui_console.py`:
  - `LogSink(max_lines: int = 2000)`: a `sys.stdout`-compatible file object. `.write(text: str) -> int`, `.flush() -> None`, `.drain() -> list[str]` returning and clearing every complete buffered line, `.text: str` returning the whole buffer. Holds at most `max_lines` lines, dropping the oldest; `drain()` honours the same cap so `text` and `drain()` agree. Also stubs `encoding`, `errors`, `isatty()`, and `fileno()` so libraries reading them inside a redirect do not crash.
  - Two contracts are load-bearing and were each established the hard way, so carry them forward:
    - `drain()` returns lines **with** their trailing `\n`. The consumer inserts them straight into a Tk `Text`, and Tk joins newline-free inserts into one run-on paragraph.
    - `drain()` **retains** an incomplete trailing line in the buffer; it must not be discarded.
  - `KeySource()`: `.push(key: str) -> None` and `.poll() -> str` returning the next pushed key in FIFO order, or `""` when empty (matching `_read_key`'s contract at `sync_runtime.py:430`).

`_run(action, worker)`: if `self._busy`, log `[gui] another operation is already running` and return. Otherwise set busy, disable the action buttons, set the status, and start `threading.Thread(target=body, daemon=True)`. `body` swaps `sys.stdout` for a fresh `LogSink` via `contextlib.redirect_stdout`, runs the worker, and calls `self.after(0, self._run_finished, action, rc)`.

`_run_finished`: if `self._closing`, return immediately (scheduling `after` on a destroyed root raises `TclError`, Review Focus 4). Otherwise drain the sink into the pane, log `[gui] <action> finished`, clear busy, re-enable buttons, reset status to `idle`.

`Play` calls `sync_runtime.run_play(None, root=self._root_dir, keys=self._keys.poll)`. It does not pass `poll_s`, so hotkey throughput stays at one key per 250 ms (Review Focus 1b) and the GUI's `Play` button doubles as `Stop` by pushing `q`.

`Scan` calls `scan_runtime.scan_with_candidates(candidates)`: the URL entry yields a one-element list built from `parse_video_id`, otherwise `pick_mv_candidates(state.artist, state.title, state.duration_s, root=self._root_dir)`.

`Fix` launches `FixerWindow` in a **separate process** with `subprocess.Popen([sys.executable, "-m", "mvsync", "fix"])` and waits on it. Never construct a second `Tk()` off the main thread (Review Focus 6). The spawned process takes the session lock transitively through its scan, which is why Task 4's lock check is what protects against racing it.

Bind `<KeyPress>` on the window and on the log pane, matching `event.keysym` against `q`, `r`, `bracketleft`, `bracketright`, `p` rather than reading `event.char`, so non-US layouts work (Review Focus 5).

## Notes for the implementer

- Task 2 must land before Task 3: `MainWindow` passes `self._keys.poll` into `run_play`, which does not accept it until Task 2.
- Never construct `tk.Tk()` in a test. The house pattern (`tests/test_gui.py` against `format_length` / `candidate_row_values`) is to test the pure helpers and keep widget wiring manual.
- `sys.stdout` swapping is process-global. `contextlib.redirect_stdout` scopes it to the worker, but `sys.stderr` is not redirected, so third-party warnings still go to the console. That is acceptable and better than losing tracebacks, but do not let the GUI imply a clean run when a library warned.
- Known limitation, deliberately not fixed here: hotkeys pushed before `_follow` starts are never read, so `q` does nothing while a video downloads (up to 90 s, `sync_runtime.py:43`). Fixing it means making startup interruptible, which is a change to `sync_runtime`'s structure rather than to the GUI, and is out of scope for this plan.
