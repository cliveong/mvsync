# MV Picker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user see the ranked MV candidates for the current Spotify track and rebuild the alignment with the one they click, without typing CLI commands, and make the automatic ranking prefer the track's own artist so covers and remakes pick correctly.

**Architecture:** A Tkinter window (stdlib, `src/mvsync/gui.py`) opened from the interactive menu (`4) fix`) or `mvsync fix`. The window shows the SMTC track, the ranked candidates (same yt-dlp search as scan), marks the candidate currently in use, and on click reuses the scan pipeline (pause, rewind, record one listen, fit, save) via a new programmatic entry point `scan_runtime.scan_with_candidates`. Saving a map prunes superseded maps for the same track so a fix always wins. Ranking gains an artist boost and stops double-counting the "Official Music Video" phrase.

**Tech Stack:** Python 3.12, tkinter (stdlib only, no new dependencies), pytest, existing yt-dlp/SMTC/loopback machinery.

**Spec:** None (brainstorming was skipped per the user's request on 2026-10-17). The decisions captured here came from that conversation: GUI picker, artist-aware ranking, fix the stored wrong Bansanka map.

## Global Constraints

- Windows-only, Python >= 3.12; no new runtime dependencies (tkinter only).
- Every path goes through `paths.py`; nothing absolute in committed code.
- Tests must run without network, real audio devices, SMTC, or mpv; anything needing them gets the `integration` or `dsp` marker.
- Console and GUI text in English; console prefixes stay `[scan]`, `[play]`, `[search]`, `[doctor]`.
- ruff line length 100; type hints on public functions; short docstrings, no decorative output.
- TDD: failing test first, run it, implement, run it, commit.
- One `session.claim` at a time: `scan_with_candidates` refuses while play/scan holds the lock.

## Review Focus

Likely failure modes, most likely first; each has a test in the task that owns the code.

1. "Use this MV" while a play session runs: must surface the session-lock error in the window, never steal the lock (Task 3 test, Task 4 messagebox).
2. Fix saves the new map but the old wrong map still wins: play loads the newest mtime, and saving prunes the rest (Task 2 tests, Task 3 prune test).
3. Mid-scan seek/pause/track change: abort cleanly, no map written, recording deleted (existing `_record_until_end` tests, Task 3 abort test).
4. yt-dlp search fails or returns nothing (offline): the window logs the error and stays usable (Task 4 error path, manual check).
5. Window closed mid-scan: no corrupt map (atomic save already), at worst a stray wav (Task 4 close guard, manual check).

def load_newest_alignment(store_dir: Path, track_id: str) -> tuple[Alignment, float, str] | None:
    """The most recently written loadable alignment for a track."""
    for match in find_alignments(store_dir, track_id):
        video_id = video_id_from_alignment_path(match)
        loaded = load_alignment(store_dir, video_id, track_id)
        if loaded is not None:
            return loaded[0], loaded[1], video_id
    return None


def prune_other_alignments(store_dir: Path, track_id: str, keep_video_id: str) -> list[Path]:
    """Delete other alignments for a track; a track has one authoritative MV."""
    removed: list[Path] = []
    for match in find_alignments(store_dir, track_id):
        if video_id_from_alignment_path(match) != keep_video_id:
            match.unlink(missing_ok=True)
            removed.append(match)
    return removed
```

def scan_with_candidates(
    candidates: list[Candidate],
    *,
    root: Path | None = None,
    on_progress: Callable[[str], None] | None = None,
) -> ScanResult:
    """Record one listen of the current track and fit it against candidates in order."""
    notify = on_progress or (lambda message: None)
    session.claim(root)
    try:
        bridge = SpotifyBridge()
        state = bridge.current()
        if state is None or (not state.artist.strip() and not state.title.strip()):
            raise ScanAborted("no Spotify session with track metadata")
        track_id = make_track_id(state.artist, state.title)
        position = _pause_and_rewind(bridge, notify)
        rec_path = paths.recordings_dir(root) / f"{candidates[0].video_id}__{track_id}.wav"
        try:
            return _record_and_fit(
                candidates,
                bridge=bridge,
                state=state,
                track_id=track_id,
                position=position,
                root=root,
                on_progress=notify,
            )
        finally:
            _discard(rec_path)
    finally:
        session.release(root)
```

- [ ] **Step 3: Implement `src/mvsync/gui.py`**

Short docstring: `"""Tkinter MV picker: see the ranked candidates for the current track and rebuild its map."""`

Layout (ttk widgets, everything in one `tk.Tk` subclass `FixerWindow`, helper `_build_ui`):

- Top frame: `track_label` (artist, title, duration; "no Spotify session" when absent), buttons `Refresh track` and `Search MVs`.
- Middle: `ttk.Treeview` columns `("#", "mv", "channel", "length", "status")`, height 8, with scrollbar; double-click opens the candidate in the browser (`webbrowser.open(video_url(id))`).
- Bottom: buttons `Open in browser`, `Copy URL`, `Use this MV`; a `status_label`; a read-only `tk.Text` log (height 6).

Behavior:

- `refresh_track()`: `SpotifyBridge().current()`; keep `self._state`; compute `make_track_id`; `in_use = load_newest_alignment(alignments_dir, track_id)`; repopulate the table if candidates exist for the same track, marking `in_use[2]`. If the track id changed since the last search, clear the table and `self._candidates` (stale rows must not be clickable). `Use this MV` is disabled while `self._candidates` is empty.
- `search()` (worker via `threading.Thread(daemon=True)`, results marshalled with `self.after(0, ...)`): `pick_mv_candidates(state.artist, state.title, state.duration_s, root=self._root)`; needs a current track, else `status_label` says so. On `RuntimeError` log the message and show `messagebox.showerror("mvsync", str(exc))`.
- `use_selected()`: read the selected row; keep `self._candidates` as returned by the search (same order as the table). `messagebox.askyesno` text: `f"Rebuild the map for {artist} - {title} using {candidate.title or candidate.video_id}?\n\nSpotify pauses, rewinds, and plays the track once ({format_length(duration)}); keep it playing untouched until it ends."` On yes, worker: `scan_with_candidates(prioritize(self._candidates, index), root=self._root, on_progress=lambda message: self.after(0, self._log, message))`; on success `messagebox.showinfo("mvsync", f"Saved a new map: {result.video_id}")` then `refresh_track()`; on `ScanAborted`/`RuntimeError` `messagebox.showerror("mvsync", str(exc))` (this is where the session-lock message lands).
- Busy guard: `self._busy` disables Search/Use/Refresh until the worker finishes via `after(0, ...)`.
- `protocol("WM_DELETE_WINDOW")`: when busy, `askyesno("mvsync", "A scan is running; closing now aborts it. Close anyway?")`.

`run_fixer`: create the window, `return 0` after `mainloop()`.
